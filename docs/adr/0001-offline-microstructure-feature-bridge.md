# 微观结构特征在 Freqtrade 引擎外预计算，回测与实盘共用同一份特征文件

Status: accepted

清算瀑布反转策略需要强平流、未平仓量、盘口深度和逐笔成交，而 Freqtrade 的数据通道
只有 K 线（`CandleType` 里没有 liquidation / open_interest，`DataProvider.orderbook()`
又会联网且只在 dry-run/live 可用）。我们决定把这类微观结构数据放在引擎之外采集与
计算，按分钟落成一份点对点的特征文件 `user_data/liquidation/<PAIR>-1m-cascade.csv.gz`，
策略在 `populate_indicators` 里按 `date` 合并回来；回测、dry-run、实盘读的是同一个文件。

## Considered Options

- **在策略内部联网取数据**：被否。会导致回测不可复现、hyperopt 反复打接口，
  且写入的实盘专属逻辑会让回测与实盘的信号产生系统性漂移。
- **改 Freqtrade 源码增加数据通道**：被否。升级引擎即失效，且桌面端是"共用 venv 调 CLI"
  的架构，补丁无法保证与上游同步。
- **只用 K 线近似（放弃盘口/逐笔）**：被否。确认条件里的"买盘恢复 / OFI 转正"正是
  区分真假反转的关键，只靠 K 线会退化成普通的超卖反弹策略。

## Consequences

- 数据一致性的责任从引擎转移到特征管线：任何口径变化（单位、时间对齐、聚合方式）
  都必须同时更新历史文件与实时采集器，否则回测与实盘不一致。
- 特征文件成为回测的前置条件：文件缺失或区间不覆盖时，策略明确不开仓并给出日志提示
  （而不是静默跑出 0 交易或"看起来正常"的结果）。
- 因为交易所不提供历史强平归档（Binance `liquidationSnapshot` 已实测 404），
  回测期的强平列为空，抛压分降级为"价格速度 + 主动买卖失衡 + OI 收缩"的代理；
  这一点必须在任何回测结论里显式标注。
